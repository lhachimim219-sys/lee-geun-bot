# بوت واتساب - Baileys

بوت واتساب بسيط مبني على [@whiskeysockets/baileys](https://github.com/WhiskeySockets/Baileys)، جاهز للاستضافة على **Render** أو **Railway** عبر GitHub.

## 📁 هيكل المشروع

```
whatsapp-bot/
├── index.js          # نقطة التشغيل: الاتصال + QR + تحميل الأوامر
├── package.json
├── .gitignore
├── plugins/           # كل ملف هنا = مجموعة أوامر
│   ├── ping.js
│   └── manga.js
└── session/           # ملفات جلسة تسجيل الدخول (لا تُرفع لـ GitHub)
```

---

## 1️⃣ الرفع إلى مستودع GitHub خاص

```bash
cd whatsapp-bot
git init
git add .
git commit -m "أول نسخة من البوت"
```

1. أنشئ مستودعًا جديدًا **Private** من [github.com/new](https://github.com/new) (لا تضف README أو .gitignore من الموقع، الملفات موجودة بالفعل).
2. اربط المستودع المحلي بالمستودع البعيد وارفع الكود:

```bash
git remote add origin https://github.com/USERNAME/REPO_NAME.git
git branch -M main
git push -u origin main
```

> ⚠️ **مهم:** المستودع يجب أن يكون **Private** لأن مجلد `session/` (إن تم رفعه بالخطأ) يحتوي مفاتيح تسجيل الدخول لحسابك على واتساب. ملف `.gitignore` المرفق يمنع رفعه أصلاً، لكن الخصوصية طبقة حماية إضافية.

---

## 2️⃣ التشغيل الأول محليًا (لتوليد الجلسة)

قبل الاستضافة، شغّل البوت مرة واحدة على جهازك لتوليد جلسة صالحة عبر مسح QR:

```bash
npm install
npm start
```

سيظهر رمز QR في الطرفية (Terminal). افتح واتساب على هاتفك:
**الإعدادات ← الأجهزة المرتبطة ← ربط جهاز** ثم امسح الرمز.

بعد نجاح الاتصال، سترى:
```
✅ تم الاتصال بنجاح بواتساب!
```

وسيتم إنشاء مجلد `session/` يحتوي بيانات تسجيل الدخول — **هذا المجلد لا يُرفع إلى GitHub** (محمي عبر `.gitignore`).

جرّب الأمر `.بينج` من أي محادثة للتأكد أن البوت يستجيب.

---

## 3️⃣ ربط الجلسة بالاستضافة

بما أن `session/` غير مرفوعة على GitHub، والاستضافات السحابية (Render/Railway) تشغّل نسخة جديدة من الكود بدون تلك الملفات، عندك خياران:

### الخيار أ — رفع الجلسة يدويًا (الأبسط للاستخدام الشخصي)
بعد التشغيل المحلي الناجح، ارفع محتوى مجلد `session/` كملفات على الاستضافة عبر:
- **Railway**: تبويب "Volumes" لإنشاء تخزين دائم، ثم رفع ملفات الجلسة إليه يدويًا عبر SSH/CLI.
- **Render**: استخدام **Disk** دائم (Persistent Disk) في إعدادات الخدمة، ورفع الملفات إليه.

### الخيار ب — متغيرات بيئة (أكثر أمانًا للنشر)
عدّل الكود لاحقًا لتخزين بيانات الجلسة (creds.json) كمتغير بيئة `SESSION_DATA` بدلًا من ملفات على القرص — مفيد إذا كانت الاستضافة لا توفر تخزينًا دائمًا (Render المجاني مثلًا يمسح القرص عند كل إعادة تشغيل).

> 📌 **الأهم:** بدون تخزين دائم (Persistent Disk/Volume)، سيطلب منك البوت مسح QR من جديد في كل مرة تُعاد فيها الخدمة (Redeploy)، لأن مجلد `session/` سيُمسح.

---

## 4️⃣ النشر على Render

1. من لوحة Render: **New → Web Service**.
2. اربط حساب GitHub واختر المستودع.
3. الإعدادات:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Instance Type:** Free (أو أعلى لبقائه شغالًا بدون توقف)
4. أضف **Disk** دائم من تبويب "Disks" وثبّت المسار على `/opt/render/project/src/session` حتى لا تُفقد الجلسة عند كل نشر جديد.
5. اضغط **Deploy** وتابع رمز QR من تبويب **Logs**.

## 4️⃣ (بديل) النشر على Railway

1. من [railway.app](https://railway.app): **New Project → Deploy from GitHub repo**.
2. اختر المستودع، وسيكتشف Railway ملف `package.json` تلقائيًا.
3. من تبويب **Variables** أضف أي متغيرات بيئة إن احتجت (مثل `BOT_PREFIX`).
4. من تبويب **Volumes** أنشئ Volume واربطه بمسار `/app/session` للحفاظ على الجلسة.
5. بعد النشر، راقب رمز QR من تبويب **Deployments → View Logs**.

## ⚙️ ملاحظات إضافية

- لتغيير رمز البادئة الافتراضي (`.`) اضبط متغير بيئة `BOT_PREFIX` (مثلاً `!`).
- لإضافة أوامر جديدة: أنشئ ملف `.js` داخل `plugins/` يُصدّر `handler` به `handler.command = [...]` — سيُحمَّل تلقائيًا عند التشغيل.
- إذا ظهرت رسالة "تم تسجيل الخروج"، احذف مجلد `session/` محليًا وكرر خطوة التشغيل الأول لإعادة ربط الجهاز.
- استخدام مكتبات كشط المواقع (مثل `cheerio` في `manga.js`) يعتمد على بنية الموقع المصدر؛ إن تغيّر تصميم الموقع، قد تحتاج تعديل المُحددات (selectors).
